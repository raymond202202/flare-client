# Win7 兼容性调研报告（实证版）

日期：2026-11-03
调研动因：用户姐姐的 Win7 装 Flare 报错；元宝提示「Win7 默认 .NET 可能只有 3.5 甚至没有」，并建议考虑 Win32/MFC/WinForms。

---

## 一句话结论

元宝说对了一半，但**漏了更致命的一层**：Flare 在 Win7 上打不开是**三重故障**，不只是 .NET 外壳的问题 —— 连 Go 引擎本身（Go 1.21+ 起官方放弃 Win7）也不能跑。三层都修好才有真 Win7 支持，而我已实测出可行做法：**引擎换 Go 1.20 重编 + 外壳换纯 Win32，单文件零依赖，体积反而更小。**

---

## 一、官方事实：Win7 到底自带什么 .NET

来源：Microsoft Learn《Install .NET Framework on Windows and Server》（官方对照表原文）

| Windows | 系统内置 .NET | 最高可装 |
|---|---|---|
| Windows 8.1 | 4.5.1 | 4.8 |
| Windows 8 | 4.5 | 4.6.1 |
| **Windows 7** | **3.5** | 4.8 |
| Windows Vista | 3.0 | 4.6 |
| Windows XP SP3 | 无 | 4.0.3 |

结论：
- **Win7 出厂只有 .NET 3.5**（SP1 为 3.5.1），元宝说对。
- 「甚至更低、甚至没有」不成立 —— Win7 一定有 3.5，且可在「启用或关闭 Windows 功能」里开关。
- 4.x 全系列**都不是系统自带**，要用户自己装。Win7 SP1 最高能装到 4.8（离线包约 110 MB，装完通常要重启）。
- Win7 已过微软全生命周期支持，这份表属历史存档。

对照我们的现状：Windows 外壳 TFM = `net452`，`Flare.exe.config` 里写着 `sku=".NETFramework,Version=v4.5.2"`。
→ **干净 Win7 上双击必然报缺 .NET，这不是概率问题，是设计问题。** 用户姐姐看到的报错就是这个。

## 二、我自己查出来的、元宝没提的一层

`engine/flare.exe` 占包体 92.6%（11,291,648 B），是 Go 编译的单文件。查 Go 官方发布说明：

> Go 1.21 起，Windows 最低要求 **Windows 10 / Server 2016**；Win7、Win8、Server 2008/2012 不再支持。

我们 go.mod 写的是 `go 1.26.10`，CI 用最新工具链 → **产出的 exe 在 Win7 上起不来**。

静态取证（扫二进制里的 Win8/Win10 专属 API 字符串）：

| 产物 | 体积 | 命中 Win8/Win10 专属 API |
|---|---|---|
| Go 1.26 现值引擎 | 11,291,648 B | `ProcessPrng`、`bcryptprimitives` |
| Go 1.20 重编引擎 | **9,519,616 B** | **无** |

`ProcessPrng` 只有 Win10 1607+ 的 bcryptprimitives.dll 才导出，Win7 上找不到 → 引擎初始化即失败。

**所以即使把 .NET 补上、壳能起来，引擎照样崩。** 这是这轮调研最重要的发现。

---

## 三、实测数据：四条原生路线真实体积

本机实测（交叉编译，非估算）：

| 方案 | 最小窗口产物体积 | Win7 | 依赖 |
|---|---|---|---|
| 纯 Win32 C++（mingw 静态 CRT） | **17,408 B（17 KB）** | ✅ 原生 | 只用系统 DLL |
| Go 1.20 + 纯 Win32（syscall） | **908,800 B（887 KB）** | ✅ 原生 | 零 |
| Go 1.20 引擎（含 SQLite） | **9,519,616 B（9.08 MB）** | ✅ | 零 |
| WPF net452（现状外壳） | 88,064 B | ❌ | .NET 4.5.2 |

C++ 版只引用 `KERNEL32/USER32/COMCTL32/msvcrt`，全是系统自带，**Win7 到 Win11 一个文件通吃**。

## 四、对元宝三个建议的逐条裁决

**1. 纯 Win32 —— 对，这是最优解。**
体积下限 17 KB，零运行时依赖，Win7~Win11 通吃。但现成 WPF UI（863 行 C# + XAML）要重写成 C++/Go 的 Win32 绘制。

**2. MFC —— 不必要。**
MFC 只是 C++ 包 Win32 的类库，静态链接也能零依赖，但产物 1~3 MB（比纯 Win32 大两个数量级），微软早已只维护不加功能，且同样要重写 UI。开发能快一点，但不值得为它引入 C++ 工具链 —— 除非和引擎同栈，否则多一套语言维护成本。

**3. WinForms —— 元宝这里说错了，它不是「原生技术」。**
WinForms 是 .NET 的 UI 框架，依赖 .NET Framework 运行时，本质和 WPF 一样要运行时。
- Win7 自带 3.5 → `net35` 的 WinForms 在 Win7 上确实开箱能跑；
- 但 **Win10/11 默认不带 .NET 3.5**（是可选的「启用 Windows 功能」），干净新机器上会弹「需要安装 .NET Framework 3.5」。
- 结果就是为了救 Win7，把 Win10/11 用户推进另一个坑，还得准备两个包 → 违背「不给用户做选择」。

**补充排除项（实测/官方已确认不适用）：**
- **Tauri / WebView2**：Win7 支持已终止，出局。
- **Electron 22**：最后支持 Win7 的版本，但包体 60 MB 起步，与「轻量」目标正面冲突。
- **Flutter Windows**：官方最低 Windows 10，出局。
- **Qt 5.15 静态链接**：Qt5 是最后支持 Win7 的大版本，Linux 客户端已是 Qt 理论上能复用代码；但 Windows 静态 Qt 要自行编译（几小时）且 LGPL 合规复杂，动态链接则要带 20+ MB DLL 和 VC++ 运行库。不如 Go 方案干净。

## 五、推荐方案（已实测可行）

**引擎**：go.mod 降到 `go 1.20`，SQLite 从 `modernc.org/sqlite v1.61.0` 降到 `v1.25.0`（连带 libc/memory 等），CI 固定 Go 1.20.14。
- 实测编译通过，产物 **9,519,616 B**，比现在**小 1,772,032 B（-15.7%）**，无任何 Win10 专属 API。
- 全代码扫描：31 个 .go 文件、8,510 行，只有 1 处用到 Go 1.21 的 `min()`（`internal/llm/llm.go:428`），改一行即可。

**外壳**：Go + syscall 直写 Win32（与引擎同语言同工具链，不引入 C++）。
- 最小 887 KB；做成完整 UI（会话列表、搜索、Markdown 渲染、设置、托盘）预计 2~4 MB。
- 单 exe 内嵌引擎 → 总体约 **10~12 MB**，零运行时依赖，Win7 SP1 到 Win11 一个文件。
- 压缩后安装包预计 **3.5~4.5 MB**，和现在的 3.9 MB 基本持平。

**代价**：Windows UI 要重写（现 WPF 863 行逻辑可参照移植），这是唯一的大工程量。

## 六、还没验证的（不敢当成结论）

1. **干净 Win7 SP1 真机/虚拟机实测**：目前全是静态取证 + 交叉编译产物分析，没有真机跑过。要下结论必须开一台 Win7 SP1 VM 实测。
2. **用户姐姐机器的具体状态**：Win7 RTM 还是 SP1、32 位还是 64 位、已装哪个 .NET。不确认这三个，无法判断她到底是卡在哪一层。
3. **Win7 RTM（未打 SP1）**：.NET 4.5.2 官方只支持 Win7 SP1，RTM 理论上连万能版都装不上。
4. **万能版（41 MB）的自包含性**：尚未拆包确认是真内置 .NET 4.5.2 运行时，还是应用 + 离线安装器引导。若是后者，「什么电脑都能装」这句话要改。

---

## 七、下一步建议顺序

1. 先问清姐姐机器的 Win7 版本 / 位数 / 已装 .NET（一条命令或一张截图就能看出来）。
2. 引擎降 Go 1.20 这件单独做、单独发版 —— 体积更小且是所有后续方案的前置，改动可控（1 行代码 + 依赖版本 + CI）。
3. 外壳重写 Win32 属于大工程，建议单开一个分支，先在 Windows 上跑通最小窗口 + 对话一条链路再铺功能。
4. 期间 Win7 用户先走万能版兜底 —— 但前提是先验证万能版真能在干净 Win7 装起来，否则等于没兜底。
