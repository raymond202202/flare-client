# flare-client 包体瘦身与「原生重写」评估

> 实测日期：2026-10-29　环境：macOS 构建机（macOS 26.5.2 / arm64 / Homebrew Qt6）、Fedora 44 KDE
> 方法：先做**依赖可达性分析**（otool -L 递归遍历 + 从主程序与必需插件出发求可达集），再**实际裁剪 + 重签 + 启动验证**，不是估算。

---

## 一、结论先说

| 方案 | macOS .app | macOS .dmg | 结论 |
|---|---|---|---|
| 现状（macdeployqt 全量） | 72 M | 36 M | 基线 |
| **删冗余文件（已实测）** | **68 M** | **30 M** | 只省 4~6 M，天花板在此 |
| **自建精简 Qt（-no-icu -no-openssl -no-dbus -no-glib）** | **≈25 M** | **≈11 M** | 推荐，工作量大头在编译 |
| 原生重写（SwiftUI / Win32） | ≈5 M | ≈3 M | **不建议**（见第五节） |

**一句话：macOS 的 72 M 里有 38.6 M 是 ICU、5.3 M 是 OpenSSL，它们是 Qt 库的编译期硬链接，删文件删不掉，换技术栈才划算——但换技术栈要重写两套客户端，成本远超收益。正解是「用裁剪参数自建一份 Qt」，一次投入、两平台受益。**

## 二、macOS 实测明细（.app 72 M 的构成）

体积前 10：

| 文件 | 体积 | 性质 |
|---|---|---|
| **libicudata.79.dylib** | **32 M** | ICU 数据表，QtCore **硬链接** |
| QtGui.framework | 5.8 M | 必需 |
| QtWidgets.framework | 5.3 M | 必需 |
| QtCore.framework | 4.9 M | 必需 |
| **libcrypto.4.dylib（OpenSSL）** | **4.4 M** | QtNetwork **硬链接** |
| libicui18n.79.dylib | 2.6 M | ICU 代码，QtCore 硬链接 |
| libicuuuc.79.dylib | 1.6 M | ICU 代码，QtCore 硬链接 |
| libgio-2.0.0.dylib | 1.5 M | 唯一真·不可达（可删） |
| QtNetwork.framework | 1.5 M | 必需 |
| libglib-2.0.0.dylib | 1.2 M | QtGui **硬链接**（事件循环） |

PlugIns 合计 2.5 M：platforms 936 K（libqcocoa 必需）、tls 648 K、imageformats 484 K、styles 244 K、networkinformation 164 K、iconengines 108 K。

### 依赖可达性分析结果

从主程序 + 六个必需插件（libqcocoa / libqmacstyle / libqsecuretransportbackend / libqjpeg / libqsvgicon / libqapplenetworkinformation）出发递归求可达集：

- **可达（必需）27 个文件**，包含 `QtDBus` `libdbus-1` `libglib` `libcrypto` `libssl` 与**全部 ICU**——即这些看着「没用」的库，Qt 二进制里就是硬链接，删了 dyld 直接拒绝启动。
- **不可达仅 13 个文件、合计 3.6 M**：libgio 1.5 M、QtOpenGL 0.5 M、libtiff 0.5 M、libwebp 及兄弟 0.5 M、liblzma 0.2 M 等。

### 裁剪 + 启动验证（真跑了）

删掉上表不可达项 + 对应 imageformats 插件 + 空目录，`codesign --force --deep -s -` 重签，`codesign --verify --deep` 通过，`open` 启动 **10 秒后进程存活（PID 94168）→ ALIVE**，`hdiutil` 重新打 UDZO：

```
裁剪后 .app = 68 M
裁剪后 .dmg = 30 M   （原 36 M）
```

**即：纯删文件的天花板是 −6 M（−17 %），到此为止。**

### 反向验证（证明删除边界）

第一轮我多删了 libssl/libcrypto → dyld 直接崩：
`Library not loaded: libssl.4.dylib  Referenced from: QtNetwork.framework`
第二轮又删 libglib → `Library not loaded: libglib-2.0.0.dylib`。
**说明「homebrew Qt 一定要 OpenSSL + glib」是编译期决定的，不是部署期能改的。**

## 三、Windows 侧（待你的 Windows 机器回家实测）

运行 `packaging/build-windows.ps1` 后按同一套方法量。预判（Qt 官方预编译包结构与 macOS 同源）：

| 组件 | 预估体积 | 可去性 |
|---|---|---|
| icudt*.dll | 28~30 M | **需自建 -no-icu** |
| Qt6Core/Gui/Widgets | 20~25 M | 必需 |
| opengl32sw.dll（软件 GL 回退） | 15~20 M | **可删**（windeployqt 加 `--no-opengl-sw`） |
| 翻译 .qm | 3~5 M | **可删**（`--no-translations`） |
| d3dcompiler_47.dll | 4~5 M | `--no-system-d3d-compiler` |
| 其他 DLL/插件 | 5~8 M | 部分可删 |

**即时可得的收益（不用自建 Qt）：加三个 flag 即可省 22~30 M。** 这比 macOS 侧能拿到的多得多，所以 Windows 第一步先改 `build-windows.ps1` 的 windeployqt 参数并量包，再决定是否自建。

## 四、Linux 侧（本机实测，已经不是问题）

- GUI 安装体积：**724 K**（`~/.flare-client/install`）——Linux 走系统 Qt，不打包 Qt。
- GUI 的 RPM 包：50 K。
- Node 引擎安装体积：21 M（`~/.flare/install`）。

对比 Go 引擎单文件：**17 M，`strip` 后 11 M**，零运行时依赖。
→ Linux 上「Go 引擎 + 系统 Qt GUI」的组合天然是**最瘦的**，Windows/macOS 才需要打包 Qt。

---

## 五、要不要用原生技术重写客户端？

### 成本侧

重写意味着 **两套独立客户端**（SwiftUI for macOS、Win32/WinUI or C# for Windows），且 Linux 侧仍要保留 Qt 版——**三套 UI 代码**。而 flare-client 是 2 万行量级的 Qt 应用（chatwidget / editor / 面板联动 / IME / 主题 / 动画），UI 你已经做到像素级敏感、Apple HIG 动效曲线都已调好。重写等于把这些全部推倒重做两遍。

### 收益侧

只解决「安装包大」这一个问题，且**有更便宜的解法**（自建精简 Qt，一次性配置，两平台复用）。

### 判定

**不重写。** 重写是拿「3 套 UI 的长期维护成本」去换「安装包 25 M → 5 M」，而用户实际下载体验的差异（30 M vs 11 M vs 5 M）在 11 M 之后就无感了。

## 六、推荐路线（按性价比排序）

### 第 1 步：Windows 打包参数优化（当天可完成，省 22~30 M）
`windeployqt` 加 `--no-opengl-sw --no-translations --no-system-d3d-compiler --no-quick-import`，量包前后对比。等 Windows 机器到手执行。

### 第 2 步：删冗余（已拿到可复制的裁剪清单）
macOS 用本文的可达性脚本生成删除列表（已省 6 M）；Windows 同理删 unreachable 插件。

### 第 3 步：自建精简 Qt（真正的解法，两平台各一次）
配置参数：
```
-no-icu -no-openssl-runtime -no-dbus -no-glib -no-feature-opengl
-skip qtdeclarative -skip qtquick3d -skip qtwebengine -skip qttools
-static-runtime（可选，进一步换体积换启动速度）
```
- Qt 6 base 源码 ≈ 1 GB，`-skip` 掉大头后 **编译 15~30 分钟**（M 系列）/ 30~50 分钟（x86 Windows）。
- 预期：**ICU 38.6 M + OpenSSL 5.3 M + dbus/glib 2.9 M 全部消失**，.app 72 → ≈25 M，dmg 36 → ≈11 M。
- 代价：以后升级 Qt 版本要重新编译一次（可用脚本+缓存，一次性成本）。
- 风险点：`-no-icu` 在 macOS 会回退到 CoreFoundation 分词（中文分词/正则行为需回归测试，中文 UI 场景要重点验一次）；`-no-openssl-runtime` 在 macOS 用 SecureTransport（已确认插件在包里），Windows 需保留 schannel 后端。

### 第 4 步：Go 引擎打包
`strip` + `-ldflags "-s -w"` → 11 M 单文件，打进 GUI 包增量仅为「11 M 减掉原 Node 引擎 21 M」= **净变瘦 10 M**。也就是说**切换 Go 之后，GUI+引擎 的合并包比现在（GUI + Node 引擎）更小**。

## 七、给「双包制」的体积账（切换 Go 之后）

| 包 | Linux | macOS | Windows（预估） |
|---|---|---|---|
| 纯引擎包（Go 单文件） | 11 M | 11 M | 12 M |
| GUI 包（含引擎，瘦身后） | 1 M（系统 Qt） | ≈36 M（25+11） | ≈50 M（40+12） |
| GUI 包（不瘦身，对照） | 1 M | 83 M | 80 M+ |
