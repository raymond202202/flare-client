## 二、两套版本号（**规范原文，不得合并**）

来源：`native/protocol/render-spec.md` 第 3.1 节

> 状态栏常显：……版本链接 `客户端 vX · 内核 flare vY`
> 状态栏两个版本号来源不同（编译期常量 vs 运行时 `version` 帧），**不得合并成一个数字**；
> 内核版本未到时显示占位，不要显示 0.0.0。

来源：`flare-client/CHANGELOG.md` 第 3–5 行

> 本文件记录 **Flare Client**（桌面客户端）的版本变更。引擎侧变更见 `raymond202202/flare` 仓库。
> 版本号单一来源：`CMakeLists.txt` 的 `project(flare-client VERSION …)`，编译期注入宏，界面/包名/属性共用一处。

### 两套编号各自的事实

| 项 | 客户端版本 | 引擎版本 |
|---|---|---|
| 编号来源 | `flare-client/CMakeLists.txt` `project(flare-client VERSION 0.6.192)` | `flare` 仓 `cmd/flare` 的 `var Version`，构建时 `-X main.Version=` 注入 |
| 当前 Release | **v0.6.192**（2026-11-03 04:19） | **v0.6.164**（2026-11-02 14:06） |
| 语义 | 整个产品的版本，用户下载时看到的 | 内部引擎版本，随客户端一起发，用户不用管 |
| 界面位置 | 状态栏右侧版本链接前半段 | 状态栏右侧版本链接后半段 |

**用户看到的「0.6.192」是客户端版本，「0.6.164」是引擎版本，两者不矛盾。**

## 三、Windows 端有两条产品线（此前被混淆，此处定性）

### 3.1 `native/windows/` —— WPF（C# / .NET）→ **已发布，是当前下载页上的 Windows 版**

- 规模：3769 行 / 11 文件，24 条提交
- 打包：`.github/workflows/native-windows.yml`
- 产物（v0.6.192 Release 实测）：
  - `flare-0.6.192-win-x64-setup.exe` **3.9 MB** —— net452 主包，系统自带 .NET 兜底
  - `flare-0.6.192-win-x64-compat-setup.exe` **41.2 MB** —— net6 self-contained，老系统带运行时
- 安装方式：NSIS 向导，零提权装 `%LOCALAPPDATA%\Flare`，开始菜单/桌面快捷方式
- 最后一条提交：`97db172 主包壳降到 net452 + 引擎内置 Win7 补丁，Win7 双击即装即用`

### 3.2 `native/windows-go/` —— Go 纯 Win32（零 .NET）→ **未发布，本地打磨中**

- 规模：2143 行 / 7 文件，6 条提交（`6e4f28d` → `960897f`）
- 提交全览：
  - `6e4f28d` 引擎内嵌进外壳，单文件双击即用；新增连接设置页
  - `53a8e5b` 修致命 bug——外壳把自己当引擎启动
  - `2914876` 加自截图能力，wine 下拿到真实画面像素证据
  - `92b857f` 字体名不再写死 Win8 才有的 "Microsoft YaHei UI"，改成回探测
  - `5286a43` 修截图上下颠倒
  - `960897f` 配色回归火焰色
- 产物：x64 13.99 MB / x86 13.79 MB / arm64 13.78 MB，PE 子系统 GUI，最低系统 6.1（Win7），仅依赖 kernel32.dll，零 .NET
- **发布次数：0**

> **关键结论**：用户能下载到的 Windows 版是 **WPF 版**（可用、完整）。Go Win32 版是更彻底的路线（不依赖 .NET），但功能尚不及 WPF 版，且从未对外发布。

## 五、助手记忆错乱实证（4 处，全部有据）

| # | 错在哪里 | 证据 | 后果 |
|---|---|---|---|
| 1 | 误以为"配色应该是浅白紫" | `native/windows-go/theme.go` 初版 `6e4f28d` 用了 `#6D4AFF`，还写了假注释"与 Qt 版保持一致"；而 `flametheme.h` 一直是火焰色（`b2d5b36 火焰主题换肤`） | 界面变成白紫，用户当场发现 |
| 2 | 上一条消息提议"只露一个版本号" | `render-spec.md:127` 明文「不得合并成一个数字」 | 提议违反自己团队定死的规范 |
| 3 | 把 Go Win32 外壳当成"当前 Windows 交付物" | 它发布次数为 0；真正发布的是 WPF 版 | 让用户以为 Windows 端无可用版本 |
| 4 | 引擎版本"不是最新" | 之前编译未注入 `-X main.Version`，吃了源码默认 `0.6.163` | 界面右下角显示旧版本号 |

**根因**：上下文过长后，助手优先相信"最近的记忆"而不是"仓库里写着的规范"。规范一直在文件里，没变过。
